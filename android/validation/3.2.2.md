# Android 3.2.2 validation

Checked on 2026-10-20 with the signed release builds in a native Android 17 emulator (API 37, Google APIs x86_64). Synthetic speech was injected through the emulator microphone. Training sharing was off.

## Matched background reproduction

Both versions used the same six second source audio, Cloud engine, Normal style and mock server. Recognition returned immediately. Formatting returned after a deliberate 20 second delay. The background switch case pressed Home, opened Android Settings, then pressed Home again after formatting began.

| Case | Version | Stop to delivery | Client formatting timer |
| --- | --- | ---: | ---: |
| Visible | 3.2.1 | 20.509 s | 20.009 s |
| Home only | 3.2.1 | 20.516 s | 20.009 s |
| Switch to Settings, then Home | 3.2.1 | 52.741 s | 51.492 s |
| Repeat switch | 3.2.1 | 52.019 s | 51.470 s |
| Switch to Settings, then Home | 3.2.2 | 20.625 s | 20.008 s |
| Repeat switch | 3.2.2 | 20.540 s | 20.006 s |
| Switch and turn screen off | 3.2.2 | 20.562 s | 20.008 s |

During the slow baseline, Android reported `CACHED_ACTIVITY`, `cached=true` and `isFrozen=true`. The server sent its response at 20 seconds; the client resumed when the test brought it forward at about 50 seconds. Those baseline completion times therefore reflect the test's resume time, rather than a fixed upper bound for the defect.

The candidate remained at `FOREGROUND_SERVICE`. With the screen off, Android reported `mWakefulness=Asleep` and the bounded `Freesia:transcription` partial wake lock was held. The microphone service was absent during processing. The processing service and wake lock were absent after completion.

With a deliberately slower 45 second formatting response, 3.2.1 enforced its timeout while visible at 30.599 seconds total (30.002 seconds formatting). Version 3.2.2 enforced the same timeout in the switched background case at 30.629 seconds total (30.002 seconds formatting), without reopening the app. The existing fallback delivered the recognized text.

These are small controlled regression tests for process suspension. They do not measure model speed or establish that all phone or network delays share this cause.

## Live Cloud and build checks

Three short recordings through the public Cloud service completed in 1.133, 0.943 and 0.953 seconds from Stop to delivery on Android 17. These are candidate smoke checks, without a matched Android 17 public Cloud baseline. Capture, encoding, recognition, formatting and delivery all completed without diagnostic warnings.

Cancelling a recording stopped its microphone service and left no processing service. The next live Cloud take completed in 0.963 seconds. Cancellation after processing starts is covered by lease unit tests and code review; it was not exercised through a VM control.

The local signed release build passed 118 unit tests; seven optional live tests were skipped. Release lint completed with no errors, two existing warnings and one existing hint in unchanged UI files. The signing certificate matches 3.2.1. Lease tests cover overlapping work and duplicate cleanup.

The implementation follows Android's [process lifecycle](https://developer.android.com/guide/components/activities/process-lifecycle), [cached app freezer](https://source.android.com/docs/core/perf/cached-apps-freezer) and [foreground service types](https://developer.android.com/develop/background-work/services/fgs/service-types) guidance. The `dataSync` service covers user requested upload and processing; scheduled recovery stays with WorkManager.
